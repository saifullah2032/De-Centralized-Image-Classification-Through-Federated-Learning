Privacy Protocol

How we protect your data through privacy-preserving edge inference and federated learning

Core Privacy Principles

Local Processing

All image analysis occurs on your local device via a three-stage Triple-Layer Consistency Pipeline. Images are first identified by a MobileNetV2 classifier, then verified by a Semantic Consistency Layer (SCL) interrogative check, and finally audited by a BLIP-VQA model. No data leaves your system.

Zero Data Transmission

Images are never uploaded or stored on central servers. Only lightweight model weights (LoRA adapters) are synchronized across the federated network. Metadata about your analysis is not logged or tracked.

Encrypted Synchronization

When participating in federated learning, LoRA adapter updates are encrypted before transmission. These lightweight tuning parameters never contain information that could reconstruct your original data.

On-Device Models

The MobileNetV2 (ImageNet-1K) classifier and Salesforce/blip-vqa-base Vision-Language Model run entirely within your local environment. No cloud dependencies for core inference or model execution.

Technical Implementation

CNN Classifier (Stage 1)
  • Model: MobileNetV2 (ImageNet-1K)
  • Execution: TensorFlow/Keras locally
  • Classes: 1000 object categories
  • Input Processing: 224x224 images
  • Memory: ~200MB RAM
  • Inference Time: 50-200ms
Semantic Consistency Layer (Stage 1.5 - NEW)
  • Type: Interrogative verification gate
  • Purpose: Prevent CNN misidentification errors
  • Method: VLM asks "Does image contain [CNN_Class]?"
  • Trigger: Activates on high CNN confidence (>70%)
  • Action: Can trigger "Global Discovery Mode"
  • Transparency: Full audit trail in PDF report
Vision-Language Model (Stage 3)
  • Model: Salesforce/blip-vqa-base
  • Execution: PyTorch on CPU/GPU locally
  • Input Processing: Images resized to 512x512 max
  • Output: Text-based insights (no raw data)
  • Memory: ~2GB RAM required
  • Inference Time: 1-3 seconds per image
Federated LoRA Adapters
  • Method: Low-Rank Adaptation for fine-tuning
  • Adapter Size: ~2-5MB per model (vs 1GB+ for full weights)
  • Synchronization: Encrypted HTTPS transmission
  • Aggregation: Federated Averaging (FedAvg) algorithm
  • Gradient Privacy: No direct gradients shared
  • Opt-out: Can disable at any time
Audit & Transparency
  • SCL Status: "Verified" or "Self-Corrected" badge in PDF
  • Full Metadata: VLM interrogative question & response
  • Processing Logs: All stages documented locally
  • Error Correction: Autonomous self-correction when VLM disagrees
  • CSV Export: Includes SCL verification status
  • Accountability: Every decision is traceable

Frequently Asked Questions

Can you see my images?

No. Images are processed only on your local device. We never receive or store raw image data. The only data transmitted is optional LoRA adapter parameters for federated learning.

What happens if I participate in federated learning?

Only encrypted, lightweight LoRA adapter updates are shared. These contain model tuning parameters, not your data. The adapters are aggregated with others via FedAvg. You can disable participation anytime.

How are LoRA adapters encrypted?

Adapters are encrypted using TLS 1.3 during transmission. The encryption keys are managed securely. Adapters themselves contain no information that could reconstruct your images.

Can you reconstruct images from LoRA adapters?

No. LoRA adapters are low-rank weight updates (~2MB) that fine-tune the base model. They cannot be inverted or used to reconstruct training data. This is mathematically impossible with the current architecture.

Is the source code auditable?

Yes. The platform source code is open source. You can review the implementation, audit the privacy protections, and verify that no data collection occurs.
